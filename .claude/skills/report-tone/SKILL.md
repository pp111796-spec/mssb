# 보고서 말투 원칙

보고서 문장을 쓰거나 고칠 때(`report.py` 템플릿, `session_synthesis.py`·`claude_client.py` 프롬프트의 문체 지시, 저장된 문구 수정 모두 포함) 아래 원칙을 따른다.

## 원칙

1. 하다체(평서형 종결 '~했다', '~이다', '~보인다')를 사용한다.
2. 코딩 용어나 변인명이 나오지 않도록 한다. 영문 id, 표정 코드(AU23 등), 범주·항목 코드, '부재로 코딩했다' 같은 채점자용 표현을 쓰지 않고 관찰된 모습으로 풀어 쓴다.
3. 수동태나 물주구문 등 번역체를 사용하지 않는다. 사람이나 행동을 주어로 삼아 능동형으로 쓴다. (예: '~가 관찰되었다' → '~했다', '이 결과는 ~를 시사한다' → '~로 보인다')
4. 보고서는 전문가 간의 의사소통을 상정하여 작성한다.
5. 분량을 늘리기 위해 유사한 말을 반복하지 않는다.
6. 유려한 문장을 만들기 위해 단어를 일부러 다른 단어로 교체하지 않는다. 같은 용어는 반복 사용하여 이해가 쉽도록 한다.
7. 항목을 개수로 지칭하지 않는다. 독자는 어떤 항목이 있는지 모를 수 있으므로 '두 항목', '공격성 관련 5개 항목 모두 근거 없음'처럼 쓰지 않고, 해당 행동을 직접 서술한다. (예: '결말 문장의 어구 반복과 이야기 완결 전후 소품(TV)으로의 화제 이동이 확인되어 존재로 보았다', '공격성과 관련된 행동은 관찰되지 않았다')

## 적용 방법

- 수정 요청을 받으면 위 원칙에 맞게 문구를 고치고, 고친 전후를 짧게 보여준다.
- 문체 지시를 프롬프트에 넣을 때는 원칙을 그대로 옮기되 예시를 하나씩 붙인다.
- 원칙끼리 부딪치면(예: 기존 프롬프트의 '~되었다' 예시가 3번과 충돌) 이 문서를 기준으로 삼고 사용자에게 알린다.

## 갱신 규칙

사용자가 "기억해", "원칙에 추가해"라고 말하면 `## 원칙` 목록 끝에 번호를 이어 붙여 추가한다. 기존 원칙과 겹치거나 충돌하면 합치거나 고친 뒤 사용자에게 알린다.
